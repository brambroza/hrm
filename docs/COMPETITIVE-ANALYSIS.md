# เทียบคู่แข่ง — empeo และ HumanSoft

ใช้คู่กับ `docs/SALES-PLAN.md` (v2.0) และ `docs/PRODUCT-DESIGN.md` (v1.1)
เวอร์ชัน 1.0 · 29 ก.ย. 2569 · สถานะ: อนุมัติแล้ว 29 ก.ย. 2569 โดยเจ้าของโครงการ · งานตรวจสอบในหัวข้อ 9 ยังต้องทำ

**ที่มาของข้อมูล:** อ่านจากหน้าเว็บสาธารณะของทั้งสองรายเมื่อ 29 ก.ย. 2569 ไม่ได้ทดลองใช้ระบบจริง
ข้อความที่คู่แข่งเขียนถึงตัวเองเป็นข้อความการตลาด ยังไม่ได้พิสูจน์ว่าทำได้ตามนั้น
**ก่อนนำตัวเลขใดไปใช้กับลูกค้า ต้องสมัครทดลองใช้ 30 วันของทั้งสองรายและตรวจซ้ำ**

## 1. สรุปผู้บริหาร

**ข่าวร้ายก่อน มี 3 ข้อ**

1. **สมมติฐานหลักของแผนการขายน่าจะผิด** แผนการขายตั้งอยู่บนความเชื่อว่าระบบสำเร็จรูปทำกฎกะและ OT ซับซ้อนไม่ได้
   แต่ทั้งสองรายประกาศว่ารองรับ HumanSoft ระบุ OT ถึงระดับ "โอทีแผนกช่างพิมพ์" "โอทีเสาร์เว้นเสาร์" และ "โอที 5 เท่า"
   ส่วน empeo ระบุกะ 3 กะ 8 ชั่วโมง กะ 2 กะ 12 ชั่วโมง และค่ากะดึก
2. **ราคาห่างกันมากกว่าที่แผนการขายประเมิน** HumanSoft เริ่มที่ 590 บาทต่อเดือนและประกาศว่าไม่คิดรายหัว
   ค่า MA ขั้นต่ำของเรา 5,000 บาทต่อเดือน สูงกว่าค่าบริการทั้งระบบของเขาในแพ็กเกจเริ่มต้น
   เครื่องคำนวณ 3 ปีบนหน้า Landing ใช้ค่ากลาง 80 บาทต่อคนต่อเดือน ซึ่งไม่ตรงกับโครงสร้างราคาของสองรายนี้
3. **เราตามหลังด้านความสามารถทุกหมวด** ตามผลตรวจระบบใน `PRODUCT-DESIGN.md` หัวข้อ 2

**ข้อสรุป:** แข่งตรง ๆ ในตลาดระบบ HR ทั่วไปไม่ได้ และไม่ควรพยายาม
ทางที่ชนะได้คือเป็น **ผู้รับทำระบบเฉพาะองค์กร** สำหรับลูกค้าที่ระบบเช่าใช้ทำให้ไม่ได้ด้วยเหตุผลเชิงโครงสร้าง ไม่ใช่เชิงฟีเจอร์

## 4. จุดที่เราชนะได้

เรียงตามความมั่นใจ จากมากไปน้อย

### 4.1 ข้อมูลอยู่กับลูกค้า และลูกค้าเป็นเจ้าของระบบ

ทั้งสองรายระบุเพียงการให้บริการบน Cloud
ลูกค้าที่มีข้อกำหนดให้ข้อมูลเงินเดือนอยู่ในเครื่องของตัวเอง หรือบริษัทแม่ต่างชาติห้ามใช้ผู้ให้บริการภายนอก ไม่มีทางเลือกในสองรายนี้
**นี่เป็นความต่างเชิงโครงสร้าง คู่แข่งเลียนแบบไม่ได้โดยไม่เปลี่ยนรูปแบบธุรกิจ**

### 4.2 เชื่อมกับระบบของลูกค้าเอง

ค่าแรงเหมาชิ้นต้องดึงยอดผลิตจากระบบการผลิต ค่าเที่ยวต้องดึงจากระบบขนส่ง
ระบบเช่าใช้ให้ API แต่ลูกค้าต้องหาคนมาเขียนส่วนเชื่อมเอง
เราเป็นบริษัทรับพัฒนาซอฟต์แวร์ งานเชื่อมระบบคืองานหลักของเรา

### 4.3 กฎที่เกินขอบเขตการตั้งค่า

ระบบเช่าใช้รองรับกฎได้เท่าที่หน้าตั้งค่ามีให้ กฎที่อยู่นอกนั้นต้องรอแผนพัฒนาของผู้ให้บริการ
**ข้อนี้ยังเป็นสมมติฐาน** ต้องพิสูจน์โดยนำกฎจริงของลูกค้าเป้าหมายไปลองตั้งในระบบทดลองใช้ของทั้งสองราย แล้วจดว่ากฎใดทำไม่ได้

### 4.4 อธิบายที่มาของทุกยอดได้

ไม่พบว่ารายใดประกาศเรื่องนี้ ถ้าตรวจแล้วเขาไม่มีจริง นี่คือจุดต่างที่สาธิตได้ในห้านาที
และตอบความกังวลของฝ่ายบัญชีกับเจ้าของโดยตรง

### 4.5 รับประกันผลคำนวณด้วยข้อมูลจริงก่อนจ่ายเงิน

ระบบเช่าใช้ให้ทดลองเอง 30 วัน ลูกค้าต้องตั้งค่าเองและตรวจเอง
เราทำให้ และเทียบกับตัวเลขของเขาให้ดู

### 4.6 ค่าใช้จ่ายไม่โตตามส่วนเสริม

ลูกค้าที่ต้องใช้ส่วนเสริมหลายรายการของ empeo จ่ายเป็นรายปีต่อเนื่อง
**ข้อนี้ใช้ได้เฉพาะเมื่อคำนวณจากใบเสนอราคาจริงแล้วตัวเลขเข้าข้างเรา** ถ้าไม่ ห้ามใช้

## 5. ปรับจุดยืนและลูกค้าเป้าหมาย

### จุดยืนเดิม

> กฎกะและ OT ของคุณซับซ้อนแค่ไหน ระบบก็คิดตามนั้น

ปัญหา: คู่แข่งทั้งสองรายพูดประโยคเดียวกันได้ และพูดอยู่แล้ว

### จุดยืนที่เสนอ

> ระบบเงินเดือนที่เป็นของคุณ อยู่ในเครื่องของคุณ เชื่อมกับระบบของคุณ
> และพิสูจน์ตัวเลขด้วยข้อมูลจริงของคุณก่อนจ่ายเงิน

### เกณฑ์คัดลูกค้าใหม่

ต้องมีอย่างน้อย 1 ข้อจากกลุ่ม ก จึงเข้าขั้นเดโม ความซับซ้อนของกฎอย่างเดียวไม่พอแล้ว

| กลุ่ม | สัญญาณ |
|---|---|
| ก. เหตุผลเชิงโครงสร้าง | ข้อมูลเงินเดือนต้องอยู่ในเครื่องของบริษัท |
| | ต้องเชื่อมกับระบบการผลิต ERP หรือระบบขนส่งที่มีอยู่ |
| | ลองระบบเช่าใช้แล้ว และมีกฎที่ระบบนั้นทำไม่ได้ พร้อมระบุกฎได้ |
| | ต้องการเป็นเจ้าของซอร์สโค้ด |
| ข. เสริม | พนักงาน 100–500 คน |
| | เข้าถึงผู้ตัดสินใจได้โดยตรง |
| | มีคนดูแลระบบฝั่งลูกค้าอย่างน้อย 1 คน |

**คำถามคัดกรองข้อแรกในการคุยครั้งแรก:** "เคยดูหรือเคยลอง empeo หรือ HumanSoft แล้วหรือยัง ติดตรงไหน"
ถ้ายังไม่เคย ให้แนะนำไปลองก่อน ถ้าเขาใช้ได้ เขาไม่ใช่ลูกค้าของเรา ถ้าเขากลับมา เขาจะมาพร้อมเหตุผลที่ชัดเจน
