## ตั้งค่าเริ่มต้นแบบเป็นขั้นตอน

หน้า `/settings/setup` รวมการตั้งค่าที่เคยกระจายอยู่หลายหน้าเป็น 6 ขั้น และบันทึกครั้งเดียวในขั้นตรวจ

| ขั้น | ถาม | ระบบปรับให้ |
|---|---|---|
| บริษัท | ชื่อ เลขผู้เสียภาษี ที่อยู่ โทรศัพท์ อีเมล | ข้อมูลองค์กร ใช้บนสลิป |
| วันและเวลาทำงาน | วันทำงาน เวลาเริ่ม-เลิก เวลาพัก | ตั้งค่าระบบ + กะปกติ + วันหยุดประจำสัปดาห์ |
| กติกาลงเวลา | เวลาผ่อนผัน เกณฑ์ขาดงาน วิธีนับ OT | กติกาลงเวลา + เวลาผ่อนผันของกะปกติ |
| วันหยุดประจำปี | รายการวันหยุดของปี | ตารางวันหยุด |
| แผนก | ชื่อแผนก | เพิ่มแผนกใหม่ |
| รอบเงินเดือน | วันที่จ่าย วิธีจ่าย ธนาคาร | ตั้งค่าระบบ |

สิ่งที่เพิ่มมาพร้อมกัน

- ก่อนหน้านี้ไม่มีหน้าจอใดให้ใส่วันหยุดประจำปีหรือวันหยุดประจำสัปดาห์ ทั้งที่การคำนวณเวลาอ่านตารางวันหยุด
- การคำนวณเวลาไม่นับวันหยุดประจำสัปดาห์เป็นขาดงานแล้ว คนที่มาทำงานในวันหยุดยังได้ชั่วโมงตามจริง
- ตรวจเลขผู้เสียภาษี 13 หลักพร้อมหลักตรวจสอบ
- แดชบอร์ดแสดงความคืบหน้าการตั้งค่าแก่ผู้มีสิทธิ์ตั้งค่า จนกว่าจะครบ
- บันทึกซ้ำได้โดยไม่เกิดข้อมูลซ้ำ ถ้าบางส่วนบันทึกไม่ผ่าน ระบบบอกเป็นรายส่วนและบันทึกส่วนที่เหลือซ้ำได้

ข้อจำกัด

- เบราว์เซอร์รวมการบันทึกหลายตารางเป็นรายการเดียวไม่ได้ จึงบันทึกทีละส่วน ถ้าต้องการให้สำเร็จหรือล้มเหลวพร้อมกันทั้งหมด ต้องย้ายไปเป็นฟังก์ชันในฐานข้อมูล
- กะปกติระบุด้วยชื่อ "กะปกติ" ถ้าผู้ใช้เปลี่ยนชื่อกะนี้ที่หน้าตั้งกะ การตั้งค่าครั้งถัดไปจะสร้างกะใหม่
- ค่าการปัดเศษ OT บันทึกได้ แต่การคำนวณยังไม่นำไปใช้ รอเครื่องคำนวณเฟส 1
- หน้าตั้งค่าเดิมยังอยู่ และมีข้อความแนะนำให้แก้ผ่านหน้าตั้งค่าเริ่มต้น
- ทดสอบการแสดงผลแล้วทุกขั้น ยังไม่ได้ทดสอบการบันทึกกับฐานข้อมูลจริง

## ยังไม่ได้ทดสอบ

สิ่งเหล่านี้ต้องมีฐานข้อมูลและการเข้าสู่ระบบจริง จึงยังไม่ได้ทดสอบ

- หน้าจอที่แก้ทั้งหมดยังไม่ได้เปิดใช้งานจริงในเบราว์เซอร์ ผ่านเพียง build
- Edge Function `create-user` ยังไม่เคยรัน
- migration 0006 ยังไม่เคยรันกับฐานข้อมูลจริง ฐานข้อมูลจริงมีโครงสร้างคลาดจากไฟล์ในโครงการ ตามที่ระบุใน `supabase/README.md`
- สลิป PDF ตรวจภาพแล้วอ่านได้ แต่สระบนกับวรรณยุกต์ที่ซ้อนกัน เช่น "ที่" วางตำแหน่งไม่สมบูรณ์ เป็นข้อจำกัดของไลบรารีสร้าง PDF

## เรื่องที่ต้องตัดสินใจ

1. **ไฟล์ lock สองไฟล์** โครงการมีทั้ง `package-lock.json` และ `yarn.lock` การติดตั้ง Vitest ทำให้ทั้งสองไฟล์เปลี่ยนมาก ควรเลือกใช้อย่างเดียว CI ที่เขียนไว้ใช้ npm
2. **ไฟล์ว่าง `src/services/__tests__placeholder`** สร้างขึ้นโดยไม่ตั้งใจระหว่างทำงาน ควรลบ รออนุญาต
3. **ลำดับการขึ้นระบบ** โค้ดใน branch นี้ต้องใช้คู่กับ migration 0001-0006 ถ้า deploy โค้ดก่อนรัน 0006 การไม่อนุมัติใบลาจะบันทึกไม่ผ่าน
